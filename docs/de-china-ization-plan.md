# Де-китаизация: стартовый план для новой сессии

Дата: 2026-09-28. Статус: **план, не исполнение**. Файл лежит в `docs/`,
потому что уйдёт в удалённый репозиторий вместе с остальной документацией,
но в индекс `docs/README.md` намеренно не вписан — это рабочий план, а не
документация пользователя.

## Цель

Убрать из интерфейса и дефолтов привязку к Китаю как к «домашнему» региону:
названия режимов, GFWList как единственный обновляемый набор, китайские
дефолты DNS. Поведение для существующих пользователей не меняется:
переименование подписей не трогает хранимые значения настроек.

## Жёсткие ограничения (нарушить = откат ревью)

- Хранимые значения настроек (`pacMode`: `whitelist`/`gfwlist`/`routingA`,
  `transparent`: `close`/`proxy`/`whitelist`/`gfwlist`/`pac`) — это API и
  база. Переименовывать **подписи**, не значения. Смена значений требует
  миграции (`service/db/configure/`, `MigrateSetting` как образец).
- Строки интерфейса — во всех 6 локалях разом (`en, zh, fa-ir, ko, pt-br,
  ru`), иначе не пройдёт `yarn i18n-check`. Проверка сравнивает наборы
  ключей, а не переводы.
- Это форк апстрима v2rayA: каждое расхождение с апстримом усложняет мердж.
  Держать дифф минимальным, не переименовывать внутренности без нужды.
- Гейты AGENTS.md на каждое изменение: `yarn lint typecheck i18n-check
  test build` в `gui`, `go build/vet/test` в `service` и `core`.

## Фазы

**P0 — подписи и discoverability (только GUI, без смены поведения).**
Нейтральные названия режимов (напр. «Прокси, кроме списка исключений» со
списком-именем?), хинт у радио про редактор RoutingA, дизейбл «Обновить
GFWList» когда режим не используется. Критерий: все 6 локалей, скриншоты
Playwright до/после на десктопе и телефоне (уже есть харнес в /tmp/opencode —
проверить, что дожил; если нет, собрать заново по `docs/running-from-source.md`).

**P1 — дефолты.** Нейтральный дефолтный DNS-апстрим вместо `223.5.5.5`
(кандидаты: `1.0.0.1`, `8.8.8.8` — решить с владельцем; затрагивает
`dnsrules.go`, `Dns.vue`, доки). Критерий: чистая установка отвечает через
новый дефолт, `dig @127.0.0.1 -p 52353` живьём.

**P2 — GFWList как частный случай.** Обобщить механизм обновления наборов
(имя набора вместо захардкоженного GFWList) ИЛИ задокументировать как
осознанное наследие апстрима и закрыть пункт. Решает владелец до старта фазы.

**P3 — доки.** `docs/user-guide*.md`, in-app `routing.md`/`transparent-proxy.md`
(en+ru), корневые README если меняются названия. Паритет EN↔RU проверять
счётчиками заголовков и блоков кода.

## Вне скоупа

Смена хранимых значений без миграции, удаление режимов whitelist/gfwlist
(ломает существующих пользователей), переводы beyond en+ru сверх правила
шести локалей для строк интерфейса, редизайн настроек.
